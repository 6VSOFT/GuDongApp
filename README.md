# 古董局中局 · 鉴宝手札

按用户提供的《桌游双—古董局中局—全规则教学影片》实现的 PWA，React + Vite + Express + Socket.IO。全员手机联机，服务器自动主持；无需真人 GM。

## 启动

```sh
npm install
npm run dev
```

电脑打开 http://localhost:5173 。同一 Wi-Fi 的手机打开 http://192.168.100.18:5173 （电脑当前局域网 IP，以实际网络为准），每人使用独立设备或浏览器会话。创建 6–8 人房间，分享邀请码，选色并准备；全员到齐后房主开局。

```sh
npm test
npm run build
npm start
```

生产服务端口默认 5173，可用 `PORT` 配置；公网运行时配置 `PUBLIC_URL=https://你的域名`，通过 HTTPS 代理至该端口。PWA 安装与离线缓存需要 HTTPS 或 localhost；普通局域网 HTTP 可联机，不能保证浏览器提供安装入口。联机始终需要可达服务器。

## 数据与隐私

本地 Node 服务把房间数据保存在 `.data/rooms.json`，可用 `DATA_DIR` 指定其他目录，不要加入版本控制。Netlify 部署把数据保存在私有 Blobs 存储 `gudong-rooms-v1`，使用强一致读取和条件写入防止并发覆盖，房间七天后过期。两种部署的持久化数据均包含真伪、角色和会话令牌的 SHA-256 哈希。客户端公共状态不包含身份、真伪表、他人手札或投票分配；私密数据只向对应会话发送。

客户端使用 localStorage 保存随机会话令牌。不要清除浏览器数据，否则不能恢复原座位。同一浏览器多标签共享身份；多人测试应使用不同设备或隔离浏览器会话。

本地服务默认单 Node 进程，使用 Socket.IO；Netlify 使用云函数和约 1.8 秒状态轮询，后台标签约 6 秒同步一次。两者共用游戏规则引擎。当前版本适合朋友同桌或小规模服务；Netlify 请求与存储用量计入平台配额。应用不传输实时语音，发言与讨论在桌边进行。

## 设计

宣纸米白、朱砂红、墨绿，宋体标题与印章元素。视觉结构沿用视频的房间号、颜色身份、兽首鉴定及私密弹窗逻辑，扩展为桌面侧栏和手机底部导航。青铜主视觉为根据视频参考生成的装饰素材，使用内置 ImageGen，文件为 `public/bronze-hero.png`。提示词保存在 `docs/asset-prompt.md`。

## GitHub 与部署

源代码仓库：https://github.com/6VSOFT/GuDongApp 。`main` 分支推送后会自动运行测试与生产构建。

线上入口：https://gudongapp.netlify.app 。Netlify 项目关联上述仓库；推送 `main` 自动部署。`netlify.toml` 设置 Node 22、`npm run build:netlify`、`dist` 发布目录及 `netlify/functions` 云函数目录；构建时 `VITE_DEPLOY_TARGET=netlify` 自动选择 HTTPS 云端传输。无需手动配置数据库或密钥；Blobs 由 Netlify 函数运行环境授权。教学视频复制到 `dist/teaching.mp4`，不会进入云函数包。`/api/game` 为动态接口，私密对局响应不进入 service worker 缓存。

需要 Node.js 22.12 或以上。GitHub 仓库存放源码；完整联机服务不能只使用 GitHub Pages 静态托管。部署到支持长期运行 Node.js 进程及 WebSocket 的服务器，执行 `npm ci && npm run build`，以 `npm start` 启动。把 `.data` 或 `DATA_DIR` 配置为持久存储，并为访问入口启用 HTTPS。环境变量需要由部署平台注入；应用不会自动读取 `.env` 文件。
